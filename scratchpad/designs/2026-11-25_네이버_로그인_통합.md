# 네이버 로그인 통합 안 (설계 · 2026-11-25 인프라부)

사장님 지시(2026-11-25): 「브랜드커넥터도 네이버고 한번만 로그인해주면 한창에서 쓰면되지」. 이 문서는 지금 흩어진 네이버 로그인 프로필을 표로 모으고, 「한 번 로그인 = 전부」에 가까워지는 안과 한계를 적는다. **확정 전에 시험(5절)으로 가능 여부를 가린다.**

## 1. 지금 상태 (코드 주석·폴더로 확인한 것)

## 2. 먼저 사실 하나: 네이버 로그인은 「프로필 안의 쿠키」다
한 프로필에 로그인해도 다른 프로필(다른 폴더)로는 퍼지지 않는다. 그래서 **「한 번 로그인 = 전부」는 프로필을 하나로 합쳐야만 된다.** 그런데 이미 한 번 합쳤다가 깨진 이력이 있다(cafe-browser.js: 블로그 발행기와 같은 프로필을 쓰다 **세션이 깨져** 카페용을 분리). 그래서 **발행기까지 전부 합치는 안은 채택하지 않는다.**

## 3. 정한 구조 (같은 계정·읽기 위주만 합친다)
1. **기준 프로필 = real_chrome(맘캘 계정)**. 여기서 이미 같이 쓰는 스마트스토어센터·브랜드커넥트·오늘의집 등은 **한 번 로그인이면 같이 산다**(이번 실측: 같은 프로필). 새로 네이버를 쓰는 읽기 위주 작업(공구톡톡 읽기·스마트스토어 긁기·사진 가져오기)도 이 프로필로 모은다(`openRealChrome`, 동시 실행은 파일 잠금이 줄 세움).
2. **발행기(블로그·카페)와 다른 사업 계정(엔잡·판다랭크)은 합치지 않는다**: 같은 프로필에서 동시에 발행하면 세션이 깨지는 이력이 있고, 계정이 다르면 섞이지 않게 해야 한다.
3. **로그인 요구는 하나로**: 카톡 한 통에 「풀린 네이버 프로필 이름들」을 나열하고 창은 기준 프로필 하나만 띄운다. 발행기 프로필이 풀렸으면 같은 글에 한 줄 더(그 창은 그 도구의 「로그인」 명령으로). 서비스마다 따로 가던 3시간 한 줄기 규칙은 「네이버(맘캘)」로 묶는다.
4. **쿠키 나눠 주기(선택, 시험 후)**: 기준 프로필의 로그인 쿠키(NID_AUT·NID_SES)를 발행기 프로필에 복사하면 「한 번 로그인」이 가능하지만, 네이버가 **기기·브라우저 지문이 달라 보이면 추가 인증을 요구하거나 로그아웃시킬 수 있다.** 이건 공식 문서로 허용·금지를 확인하지 못했다 → 5절 시험에서 실제로 되는지·오래 가는지 본다. 되더라도 규칙 0-LG 1(「비밀번호는 프로그램이 다루지 않는다」)에는 해당하지 않는다(쿠키 값은 같은 PC 안에서만 옮기고 출력·기록하지 않는다).

## 4. 지키는 것
- 쿠키 값 출력·기록 금지(길이·해시 앞 8자리만). 프로필 폴더는 레포 밖, 백업 제외(이미 그렇다).
- 같은 프로필을 두 도구가 동시에 열지 않는다(real_chrome 잠금, 최대 3분 대기).
- 「로그인 상태 유지」 체크가 필요하다. 체크하지 않으면 세션 쿠키가 크롬을 닫을 때 사라진다(2026-11-25 실측: 사장님 로그인 직후 서버 반영이 실패한 사이 창이 닫혀 로그인이 풀렸다).

## 5. 시험(확정 조건)
1. 기준 프로필에 로그인 → 스마트스토어센터·브랜드커넥트·카페 글쓰기 화면이 각각 로그인된 채로 열리는지(같은 계정 확인).
2. 쿠키 복사 시험: 시험용 새 프로필에 NID_AUT/NID_SES 복사 → 네이버가 로그아웃시키는지 24시간·72시간 관찰. 실패하면 4번은 접는다.
3. 로그인 한 번 → 3시간 한 줄기 카톡 하나 → 창 하나로 끝나는지.

## 6. 하지 않는 것
발행기 프로필 병합, 엔잡·판다랭크 계정 섞기, 비밀번호 입력 자동화.
