## 1. 핫딜 카톡 발송봇 결함 분석 및 조치 요구사항 (도쿄 VM)

### ⚠️ 현재 상태
- **VM 환경**: LightNode 도쿄 가상 윈도우 (`38.60.212.31`)
- **조치 완료**: 현재 VM 내 `python.exe` 프로세스 전면 강제 종료 및 스케줄러(`RunKakaoBot`) 비활성화 완료 (발송 완전 중단 상태).

### 🛠️ 클로드 코드 / 방장 매니저팀 수정 과제 3가지

#### ① 다른 채팅방 발송 절대 금지 (화이트리스트 엄격 고정)
- **원인**: 현재 `find_open_hotdeal_chat()`이 제목에 "핫딜"과 ("맘캘" 또는 "공지")가 들어간 활성 창을 찾는데, 사장님이 띄워둔 다른 오픈채팅방이나 개인톡 창에 키워드가 걸리면 그 방으로 메시지가 날아가는 치명적 사고 발생.
- **요구사항**:
  - 발송 대상 방의 정확한 창 제목인 **`[맘캘린더] 핫딜공지방`** 전체 문자열과 정확히 일치(`t.strip() == "[맘캘린더] 핫딜공지방"`)할 때만 타깃팅.
  - 다른 방, 개인 채팅방, 기타 오픈채팅방에는 **절대로** 포커스나 입력을 주지 않도록 2중 3중 안전장치 필수.

#### ② 야간 방해금지 시간대 엄격 적용 (심야 발송 원천 차단)
- **원인**: 새벽 3시 30분 등 심야에 새 핫딜이 수집되자마자 봇이 단톡방에 메시지를 연속 발송하여 사장님 및 단톡방 손님들의 수면을 방해함.
- **요구사항**:
  - **밤 22:00 ~ 익일 아침 09:00 (KST 기준)** 사이에는 카카오톡 발송 로직 자체를 슬립(SKIP) 처리.
  - 수집된 핫딜은 DB에만 쌓아두고, 단톡방 실시간 발송은 활동 시간대(09:00 ~ 22:00)에만 돌도록 락.

#### ③ 서버 타임존 및 표시 시간 KST 동기화
- **조치 완료**: 가상 윈도우 타임존을 `Korea Standard Time (UTC+09:00)`으로 변경 완료 (`tzutil /s "Korea Standard Time"`).
- **요구사항**: 봇 코드 내부에서도 시간 계산 시 `timezone('Asia/Seoul')`을 명시하여 일본/중국 시간 오차 원천 방지.

## 2. Cloudflare 무료 요청량 급증 원인 분석 및 최적화 과제

### 📊 현황 및 원인 분석
- 네이버 메일로 **Cloudflare Workers 일일 요청량 75~76% 도달 경고 메일** 수신 (무료 플랜 일 10만 건 한도 중 약 7.6만 건 소진).
- **원인 분석**:
  1. **동적 썸네일 워커 (`r.momcalendar.com`)**: 카카오톡, 네이버 카페, 웹 유입 시 링크 미리보기 크롤러(kakaotalk-scrap, facebookexternalhit 등) 및 일반 방문자 리다이렉트가 워커를 호출.
  2. **루프 또는 과다 호출 의심**: 핫딜봇이나 수집기가 `r.momcalendar.com` 주소를 지속적으로 검증/조회하거나, 봇이 단톡방에 올린 링크를 외부 봇들이 대량 스크랩하면서 워커 호출 수가 단시간에 튐.
  3. **캐싱 부재**: 워커 응답에 `Cache-Control: public, max-age=86400` 등 Cloudflare 엣지 캐싱이 걸려있지 않으면 매 스크랩마다 워커 CPU 실행 횟수가 카운트됨.

### 🛠️ 클로드 코드 / 방장 매니저팀 최적화 과제
1. **Cloudflare Worker 엣지 캐싱 적용**:
   - `r.momcalendar.com` 워커 응답 헤더에 강력한 브라우저/CDN 캐싱 헤더(`s-maxage=86400, max-age=3600`)를 설정하여, 동일 핫딜 ID에 대한 스크랩 요청은 워커를 매번 재실행하지 않고 엣지 캐시에서 반환하도록 처리.
2. **Workers 요청량 모니터링 및 필요 시 유료 전환 대비**:
   - 트래픽이 자연 증가한 것이라면 월 $5 유료 플랜(월 1,000만 건) 전환 여부를 사장님께 승인받아 조치.
